\section{Week 16}
\sol{16.1}{The fact \code{hb : g b = c}, obtained by unpacking \code{hg c}, says that $b$ is a preimage of the target $c$ under $g$. The fact \code{ha : f a = b}, obtained by unpacking \code{hf b}, says that $a$ is a preimage of $b$ under $f$.

The witness must lie in $A$ because the composition \code{fun x => g (f x)} takes its inputs from \code{A}, the domain of $f$: after \code{intro c}, the goal asks for some \code{x} in \code{A} with $g(f(x))=c$. The witness $a$ has this type because it came from \code{hf b}, which provides an element of \code{A} sent to $b$ by $f$; proposing $b$, which lies in $B$, would be a type error.}
\sol{16.2}{An element lies in the union $S\cup T$ when it lies in $S$ or in $T$, so union is represented by the disjunction of the two membership predicates:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
def join {A : Type} (s t : A -> Prop) : A -> Prop :=
  fun x => Or (s x) (t x)

theorem preimage_join {A B : Type} (f : A -> B)
    (s t : B -> Prop) (x : A) :
    Iff (preimage f (join s t) x)
      (join (preimage f s) (preimage f t) x) := by
  rfl
\end{lstlisting}
\end{minipage}\par

As for \code{preimage\_meet}, the left side unfolds to \code{join s t (f x)} and the right side to \code{Or (preimage f s x) (preimage f t x)}, and both then to \code{Or (s (f x)) (t (f x))}, so \code{rfl} proves the equivalence. In ordinary notation, this is the identity $f^{-1}(S\cup T)=f^{-1}(S)\cup f^{-1}(T)$ of Exercise~\ref{ex:3.4}.}
\sol{16.3}{As in Section~\ref{ch16:sec:second}, write \code{Second r v w} as \code{And P (And Q R)}. The first claim is $P$, the first component of \code{h}, and the second is $R$, the second component of the second component:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
theorem second_not_self {V : Type}
    (r : V -> V -> Prop) (v w : V)
    (h : Second r v w) : Not (w = v) := by
  exact h.left

theorem second_route {V : Type}
    (r : V -> V -> Prop) (v w : V)
    (h : Second r v w) :
    Exists (fun u : V => And (r v u) (r u w)) := by
  exact h.right.right
\end{lstlisting}
\end{minipage}\par
Had \code{Second} been defined with the shape \code{And (And P Q) R}, the same two facts would be \code{h.left.left} and \code{h.right}.}
\sol{16.4}{The new theorem has the original conclusion and one more hypothesis, \code{h : False}. Since \code{False} has no proof, nobody can supply this hypothesis, so the new theorem can never be applied. It says only that the conclusion would follow \emph{if} \code{False} were provable, which is true of every conclusion, by \code{False.elim}; it says nothing about whether the conclusion follows from the original hypotheses, which was the question. Nor need Lean's output reveal the change: the new proof needs no \code{sorry}, \code{\#print axioms} may report no axioms, and a warning about unused hypotheses, as for \code{surj\_comp\_assumed}, is easy to overlook and absent when the original theorem had no hypotheses, as for \code{impossible\_context}. Only a comparison of the new statement with the original, hypothesis by hypothesis, is sure to reveal the change.}
\sol{16.5}{\emph{Step 1: compare the statement with the intended one.} Fill in the two-column table of Section~\ref{ch16:sec:statement} from the theorem's parameters and conclusion, including the type of every variable. A changed domain, such as \code{Nat} where integers were meant, shows up here as a mismatch of types.

\emph{Step 2: read the definitions.} Compare the body of each definition that the statement uses with the mathematical definition. A missing exclusion, such as a version of \code{Second} without \code{Not (r v w)}, shows up here and nowhere else, because the name of the definition stays the same.

\emph{Step 3: check the proof.} Run Lean on the whole file, wait until it has finished, read every warning, and run \code{\#print axioms} on the theorem. An unfinished proof shows up as the warning \code{declaration uses 'sorry'} at the declaration that contains the gap, and as \code{sorryAx} in the axiom list of every theorem that depends on it.

All three steps are needed, because each problem passes the other two: a complete proof about \code{Nat} where integers were meant, with correct definitions, passes Steps~2 and~3, a complete proof about a definition with a missing exclusion passes Steps~1 and~3, and a correct statement with an unfinished proof passes Steps~1 and~2.}
\sol{16.6}{The three kinds of check differ in what is checked and in how many cases they cover.
\begin{itemize}
\item \emph{A finite test in Python.} At length $5$, the program of Section~\ref{appD:sec:experiments} runs through all $2^5=32$ sign sequences and finds exactly $4$ Barker sequences (Section~\ref{ch14:sec:experiment}). This covers $32$ cases and no others, and the answer is only as reliable as the program's translation of the definitions, which no checker compares with the code.
\item \emph{A Lean proof about specific objects.} The periodic correlation at shift $1$ of the sequence $(1,1,1,-1)$ is $a_0a_1+a_1a_2+a_2a_3+a_3a_0=0$:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
theorem corr_shift_one :
    (1 : Int) * 1 + 1 * 1 + 1 * (-1) + (-1) * 1 = 0 := by
  rfl
\end{lstlisting}
\end{minipage}\par
Lean checks this proof completely, but it covers one case: one sequence and one shift. (Even here the encoding must match the definition: the last product, $a_3a_0$, is the wrap-around term.)
\item \emph{A universal theorem in Lean.} The theorem \code{preimage\_meet} holds for all types $A$ and $B$, every function $f$, all predicates \code{s} and \code{t}, and every element \code{x}: one proof covers infinitely many cases.
\end{itemize}}
