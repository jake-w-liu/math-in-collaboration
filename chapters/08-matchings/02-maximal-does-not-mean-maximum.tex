\section{Maximal does not mean maximum}\label{ch08:sec:maximal}
In the Ada--Ben graph, the greedy procedure that gives Ada task~$1$ gets stuck at the matching $\{\text{Ada--}1\}$, although $\{\text{Ada--}2,\ \text{Ben--}1\}$ solves the problem. Two words describe the difference.

\par\noindent\begin{minipage}{\linewidth}
\begin{definition}[Maximal and maximum matchings]\label{ch08:def:maximal}
A matching $M$ is \emph{maximal} if no edge can be added to it: for every edge $e$ of the graph that is not in $M$, the set $M\cup\{e\}$ is not a matching. A matching $M$ is \emph{maximum} if no matching in the graph has more edges than $M$.
\end{definition}
\end{minipage}\par

The matching $\{\text{Ada--}1\}$ is maximal, because each of the other two edges shares an endpoint with Ada--$1$: Ada--$2$ shares Ada, and Ben--$1$ shares task~$1$. But it is not maximum, because $\{\text{Ada--}2,\ \text{Ben--}1\}$ has two edges. To get from the first matching to the second we must remove Ada--$1$, and a greedy procedure never removes anything, so it can stop at a maximal matching that is not maximum.

Every maximum matching is maximal: if some edge $e$ could be added to $M$, then $M\cup\{e\}$ would be a matching with one more edge than $M$. The example shows that the converse is false.

\pauseq{Is the empty matching maximal?}{Only when the graph has no edges. A single edge is always a matching, since there is no second edge for it to share an endpoint with, so any edge of the graph can be added to the empty matching. If there are no edges, there is nothing to add, and the empty matching is both maximal and maximum.}

\subsection*{Comparison with Chapter~\ref{ch:structure}}
Section~\ref{ch06:sec:order} defined maximal and maximum elements of a partial order. For the matchings of a graph ordered by inclusion, being maximal, that is, contained in no other matching, agrees with Definition~\ref{ch08:def:maximal}. If an edge $e$ can be added to $M$, then $M\cup\{e\}$ is a larger matching containing $M$. Conversely, if a matching $M'\ne M$ contains $M$, then any edge $e$ of $M'$ not in $M$ can be added to $M$: the set $M\cup\{e\}$ lies inside $M'$, and removing edges from a matching cannot create a shared endpoint.

\emph{Maximum} is different. A maximum in the sense of Section~\ref{ch06:sec:order} would be a matching containing every other matching, but the Ada--Ben graph has no matching containing both Ada--$1$ and Ben--$1$. For matchings, \emph{maximum} always means \emph{largest number of edges}. If students $a$ and $b$ both accept tasks $1$ and $2$, then $\{a\text{--}1,\ b\text{--}2\}$ and $\{a\text{--}2,\ b\text{--}1\}$ are both maximum, and neither contains the other. So an extremal argument (Section~\ref{ch07:sec:walks}) that begins ``take a largest matching'' must say which kind it means: one contained in no other matching, or one with as many edges as possible.

\subsection*{A matching as a function}
A matching $M$ that saturates $L$ describes a function $f:L\to R$ (Chapter~\ref{ch:maps}): $f(s)$ is the partner of $s$. Each $s$--$f(s)$ is an edge, and $f$ is injective (Section~\ref{ch03:sec:injsurj}), since two students with the same task $t$ would give two edges of $M$ sharing the endpoint~$t$. Conversely, if $f:L\to R$ is injective and each $s$--$f(s)$ is an edge, these edges form a matching that saturates $L$. Each student lies on one of them, and two of them, for students $s\ne s'$, have different tasks $f(s)\ne f(s')$ by injectivity; as $L$ and $R$ are disjoint, no student is a task, so the two edges share no endpoint. Both conditions are needed. In the Ada--Ben graph, $f(\text{Ada})=f(\text{Ben})=1$ satisfies the edge condition but is not injective, while $f(\text{Ada})=1$, $f(\text{Ben})=2$ is injective, but Ben does not accept task~$2$.
