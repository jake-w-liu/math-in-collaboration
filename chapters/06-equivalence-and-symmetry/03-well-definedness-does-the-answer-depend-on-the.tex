\section{Well-definedness: does the answer depend on the representative?}\label{ch06:sec:well-defined}
We would like to add residue classes by the natural rule: choose a representative of each class, add the two integers, and take the class of the sum,
\[
[a]_m+[b]_m=[a+b]_m.
\]
But a class has many representatives, and the rule does not say which ones to choose. If two people choose different representatives of the same two classes, do they always get the same answer? If not, the rule does not define an addition of classes at all. Try this with $[1]_4+[2]_4$. Using the representatives $1$ and $2$ gives $[3]_4$. Choosing $5$ and $6$ instead gives $[11]_4$, which is the same class, because $11-3=8$ is a multiple of four. The integer sum changes, but its class does not. Here is why this always happens.

Suppose the first person uses $a$ and $b$, and the second uses $a'$ and $b'$, where $[a']_m=[a]_m$ and $[b']_m=[b]_m$. By Proposition~\ref{ch06:prop:classes}(b), $a'\equiv a$ and $b'\equiv b\pmod m$, so $a'=a+mk$ and $b'=b+m\ell$ for some integers $k$ and $\ell$. Then
\[
a'+b'=a+b+m(k+\ell).
\]
Since $k+\ell$ is an integer, $m$ divides $(a'+b')-(a+b)$, and so $[a'+b']_m=[a+b]_m$.

A rule whose inputs are classes, but which is computed from chosen representatives, is called \emph{well-defined} when its output depends only on the classes and not on which representatives were chosen. We have just shown that addition of residue classes is well-defined. Notice that the calculation did not prove $a'+b'=a+b$, which is usually false: $5+6=11$, not $3$. It proved that the two sums differ by a multiple of $m$, which is exactly what is needed for the two output classes to be equal. Before asking whether two outputs agree, ask what kind of object the output is.

\subsection*{Rules that fail, and how to spot them}
Try to define an integer-valued function $F$ on $\ZZ/4\ZZ$ by $F([a]_4)=a$. Since $[1]_4=[5]_4$, the rule would give both $F([1]_4)=1$ and $F([5]_4)=5$ for the same input. A function must give exactly one output for each input (Section~\ref{ch03:sec:functions}), so this rule does not define a function. We can repair it by saying which representative to use: let $F([a]_4)$ be the unique member of $[a]_4$ in $\{0,1,2,3\}$, that is, $a\bmod4$ (Section~\ref{ch06:sec:residues}). Now the output is determined by the class itself; for instance, $F([5]_4)=F([1]_4)=F([-7]_4)=1$.

The same check catches proposals that sound reasonable, such as ``the parity of a class modulo three is the parity of any of its representatives.'' Here $0$ and $3$ represent the same class modulo three, and $0$ is even while $3$ is odd, so the rule does not define anything. A single pair of representatives that gives different answers is enough to show that a rule is not well-defined. To show that a rule \emph{is} well-defined, we need an argument that covers all representatives, like the calculation for addition above. Does the parity rule fare better for classes modulo four?

\pauseq{Does the rule $G([a]_4)=[a]_2$ depend on the representative? What does the answer tell you about the parity of the members of a class modulo four?}{It does not. If $[a']_4=[a]_4$, then $a'=a+4k$ for an integer $k$, so $a'-a=2(2k)$ and $[a']_2=[a]_2$. So $G$ is a well-defined function from $\ZZ/4\ZZ$ to $\ZZ/2\ZZ$. Since $[0]_2$ is the set of even integers and $[1]_2$ the set of odd integers, $G([a]_4)$ records the parity of $a$, and all members of a class modulo four have the same parity. The step that made this work is that $2$ divides $4$; Exercise~\ref{ex:6.5} explores this further.}

The map $G$ loses information: it sends both $[0]_4$ and $[2]_4$ to $[0]_2$, so it is not injective. Yet it respects addition. Addition on $\ZZ/2\ZZ$ is well-defined by the calculation above with $m=2$, and for all integers $a$ and $b$,
\[
G([a]_4+[b]_4)=G([a+b]_4)=[a+b]_2=[a]_2+[b]_2=G([a]_4)+G([b]_4).
\]
(The first and third equalities are the rules for adding classes, and the second and fourth are the definition of $G$.) So adding first and then applying $G$ gives the same result as applying $G$ first and then adding: a map can respect addition without keeping every distinction between its inputs. Section~\ref{ch06:sec:structure} gives this property a name.
