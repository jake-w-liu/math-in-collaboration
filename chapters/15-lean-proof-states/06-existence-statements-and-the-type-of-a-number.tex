\section{Existence statements, and the type of a number}\label{ch15:sec:exists}
To prove an existence statement, we name a witness and check that it has the required property (Section~\ref{ch04:sec:directions}). For example, to prove that some natural number $n$ satisfies $n+1=4$, we offer the witness $3$ and check that $3+1=4$. In Lean:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
theorem a_witness : Exists (fun n : Nat => n + 1 = 4) := by
  exact Exists.intro 3 rfl
\end{lstlisting}
\end{minipage}\par

In Lean, the statement $\exists n\in\NN:\ n+1=4$ can be written as \code{Exists (fun n : Nat => n + 1 = 4)}, and the infoview displays it more briefly as $\exists$\,\code{n, n + 1 = 4}. The part \code{n : Nat} after \code{fun} says that the input \code{n} is a natural number. So the input to \code{Exists} is a function that turns each natural number $n$ into the proposition $n+1=4$. Applied to $3$, this function gives the true proposition \code{3 + 1 = 4}; applied to $2$, it gives the false proposition \code{2 + 1 = 4}. The whole expression says that at least one natural number has this property.

To prove the statement, \code{Exists.intro} takes two inputs: a witness, here $3$, and a proof that the witness has the property, here a proof of \code{3 + 1 = 4}. That proof is \code{rfl}. This time \code{rfl} is not a tactic on a line of its own but an input to \code{Exists.intro}. Inside an expression, \code{rfl} is the name of a proof object, the proof that an object equals itself. Lean accepts it as a proof of \code{3 + 1 = 4} because \code{3 + 1} reduces to \code{4}, so the two sides are the same object. If we offered the witness $2$ instead, Lean would ask for a proof of \code{2 + 1 = 4}, and \code{rfl} would fail, because that equation is false.

Using a hypothesis that says something exists involves the same two pieces, the witness and its property. If all we know is that some number has a property, we cannot yet refer to that number or use it in a calculation. First we must give it a name and record its property, as a paper proof does when it says ``let $n$ be such a number, so that $n+1=4$.'' The complete proof about surjective functions in Section~\ref{ch16:sec:surj} does this unpacking with the tactic \code{cases}, and it also shows a witness that has to be built from other information.

\subsection*{The type of a number decides what subtraction means}
The witness $3$ had to be a natural number, because the statement declared \code{n : Nat}. The type of a variable matters in a second way too: it decides what the arithmetic symbols mean. A natural number cannot be negative, so subtraction of natural numbers needs a rule for the case in which the usual answer would be negative. Lean's rule is that natural-number subtraction is \emph{truncated} at zero: if $a\ge b$, then \code{a - b} is the usual difference, and if $a<b$, then \code{a - b} is $0$. The notation \code{(e : T)} tells Lean to read the expression \code{e} as an object of type \code{T}, and here it decides which subtraction the minus sign means. Thus \code{(7 - 10 : Nat)} is $0$, while \code{(7 - 10 : Int)} is $-3$, because \code{Int}, Lean's name for the integers $\ZZ$, contains negative numbers. To see this, put the line \code{\#eval (7 - 10 : Nat)} in your file, outside any proof. The command \code{\#eval} asks Lean to compute an expression. The result \code{0} appears in the infoview when the cursor is on that line, and \code{lean proofs.lean} prints it too; this output is a result, not an error message. The line \code{\#eval (7 - 10 : Int)} gives \code{-3}.

Truncated subtraction breaks familiar laws. For integers, $(a-b)+b=a$ always holds. For natural numbers it fails whenever $a<b$: in \code{Nat}, the expression \code{(7 - 10) + 10} equals $0+10=10$, not $7$. So an argument that subtracts a larger number from a smaller one, and then treats the result as negative, cannot be copied unchanged into natural-number subtraction. On paper, too, a statement can change when the domain of its variables changes: the equation $x+3=1$ has the solution $x=-2$ among the integers, but no solution among the natural numbers. This is why the statement contract of Habit~2 (Section~\ref{sec:magnitude}) records the domain of every variable. When an assistant offers to repair a formal proof, check whether it has quietly changed the kind of number being used.
