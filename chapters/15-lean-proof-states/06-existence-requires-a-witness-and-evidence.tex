\section{Existence requires a witness and evidence}\label{ch15:sec:exists}
To prove an existence statement, we name a witness and check that it has the required property (Section~\ref{ch04:sec:directions}). For example, to prove that some natural number $n$ satisfies $n+1=4$, we offer the witness $3$ and check that $3+1=4$. In Lean:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
theorem a_witness : Exists (fun n : Nat => n + 1 = 4) := by
  exact Exists.intro 3 rfl
\end{lstlisting}
\end{minipage}\par

Lean writes the statement $\exists n\in\NN:\ n+1=4$ as \code{Exists (fun n : Nat => n + 1 = 4)}. The input to \code{Exists} is a function that turns each natural number $n$ into the proposition $n+1=4$, so the whole expression says that some natural number has this property. The infoview displays it more briefly as $\exists$\,\code{n, n + 1 = 4}. To prove it, \code{Exists.intro} takes two arguments: a witness, here $3$, and a proof that the witness has the property, here a proof of \code{3 + 1 = 4}. That proof is \code{rfl}, because \code{3 + 1} reduces to \code{4}. If we offered the witness $2$ instead, Lean would ask for a proof of \code{2 + 1 = 4}, and \code{rfl} would fail, because that equation is false. In harder existence proofs the witness is less obvious, and showing that it has the property may take a real argument; Chapter~\ref{ch:lean2} gives an example.

Using an existential hypothesis also involves two pieces. If all we know is that some number has a property, we cannot yet compute with that number. First we must give it a name and record its property, as a paper proof does when it says ``let $n$ be such a number, so that $n+1=4$.'' In Chapter~\ref{ch:lean2}, the tactic \code{cases} does this unpacking in a complete proof about surjective functions.

\subsection*{The type of a number changes the available operations}
A natural number cannot be negative, so subtraction of natural numbers needs a rule for the case in which the usual answer would be negative. Lean's rule is that natural-number subtraction is \emph{truncated} at zero. If $a\ge b$, then \code{a - b} is the usual difference; if $a<b$, then \code{a - b} is $0$. Thus \code{(7 - 10 : Nat)} is $0$. In contrast, \code{(7 - 10 : Int)} is $-3$, because \code{Int}, Lean's name for the integers $\ZZ$, contains negative numbers. The notation \code{(e : T)} tells Lean to read the expression \code{e} as an object of type \code{T}; here it decides which subtraction the minus sign means. You can ask Lean to compute such an expression with the command \code{\#eval}. The line \code{\#eval (7 - 10 : Nat)} prints \code{0}, and \code{\#eval (7 - 10 : Int)} prints \code{-3}.

Truncated subtraction breaks familiar laws. For integers, $(a-b)+b=a$ always holds. For natural numbers it fails whenever $a<b$: in \code{Nat}, the expression \code{(7 - 10) + 10} equals $0+10=10$, not $7$. So an argument that subtracts a larger number from a smaller one, and then treats the result as negative, cannot be copied unchanged into natural-number subtraction. The same question arises on paper whenever notation leaves the domain of a variable unstated, which is why the statement contract of Habit~2 (Chapter~\ref{ch:logic}) records the domain of every variable. When an assistant offers to repair a formal proof, check whether it has quietly changed the kind of number being used.
