\section{Reading Lean's basic notation}\label{ch15:sec:symbols}
One symbol appears in almost every line of Lean: the colon. An expression \code{a : T} says that \code{a} is an object of type \code{T}; read the colon as ``is a'' or ``has type.'' Because propositions are types and their proofs are objects of those types, the one symbol serves three purposes:
\begin{itemize}
\item \code{n : Nat} says that $n$ is a natural number. The type \code{Nat} is Lean's name for $\NN$, and, as in this book, it includes zero.
\item \code{P : Prop} says that $P$ is a proposition, in the second sense of Section~\ref{ch01:sec:roles}: a statement that is either true or false, whether or not anyone has proved it.
\item \code{hp : P} says that \code{hp} is a proof of $P$, also called \emph{evidence} for $P$. When it is assumed rather than constructed, it is a \emph{hypothesis}; by convention, names of hypotheses begin with \code{h}.
\end{itemize}

Lean writes function application with a space instead of parentheses: \code{f x} means $f(x)$. Parentheses only group, so \code{f (x + 1)} means $f(x+1)$, while \code{f x + 1} means $f(x)+1$. A function can also be written without a name: \code{fun x => x + 1} is the function $x\mapsto x+1$, and \code{(fun x => x + 1) 2} gives \code{2 + 1}, which is $3$.

Do not confuse \code{:=} with \code{=}. The symbol \code{:=} means ``is defined as'' or ``is proved by'': it attaches a definition to a name, or a proof to a theorem. The sign \code{=} means equality inside statements, as on paper.

\subsection*{Reading a declaration by its parts}
Here is a definition:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
def twice (n : Nat) : Nat := n + n
\end{lstlisting}
\end{minipage}\par
The word \code{def} announces a definition, named \code{twice}. The part \code{(n : Nat)} declares the input, a natural number \code{n}, the \code{: Nat} after it declares the type of the output, and after \code{:=} comes the rule. So \code{twice} is the function $\NN\to\NN$ given by $n\mapsto n+n$.

A theorem is declared in the same way: the word \code{theorem} and the theorem's name, then its \emph{parameters}, if any, which are the objects and hypotheses it talks about, each in parentheses like \code{(n : Nat)}. A colon follows, and after it the \emph{claim}, the proposition that the theorem asserts. Last come \code{:=} and the proof; the word \code{by} says that the proof is given by tactics on the lines that follow. This theorem has no parameters:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
theorem twice_two : twice 2 = 4 := by
  rfl
\end{lstlisting}
\end{minipage}\par

To check such a claim, Lean can \emph{reduce} expressions: it replaces a defined name by its definition and carries out arithmetic on specific numbers. Here \code{twice 2} reduces to \code{2 + 2} and then to \code{4}. The tactic \code{rfl} (short for \emph{reflexivity}, the fact that every object equals itself) proves an equality whose two sides reduce to the same expression, as both sides of \code{twice 2 = 4} do. The definition is a choice, with nothing to prove; the theorem is a claim about that choice. Had we defined \code{twice n} to be \code{n + 1}, the claim would amount to the false equation $3=4$, and \code{rfl} would fail.

The tactic \code{rfl} has a limit. The equation \code{twice n = 2 * n} holds for every natural number $n$, and each instance, such as \code{twice 5 = 2 * 5}, is proved by \code{rfl}, because both sides reduce to \code{10}. But for a variable $n$, the left side reduces only to \code{n + n} and the right side stays \code{2 * n}. These are different expressions, so \code{rfl} fails; a proof for every $n$ needs an argument that works for a variable, such as induction (Chapter~\ref{ch:induction}).

Renaming \code{twice} everywhere would not change what is proved, because names carry no mathematical content: Lean would accept a theorem called \code{all\_problems\_solved} whose claim is only \code{0 = 0}. To know what a theorem says, read its parameters, which include its hypotheses, and the claim after its colon.

\subsection*{A proposition and a proof of it are different objects}
The expression \code{2 + 2 = 5} is a perfectly good proposition, an object of type \code{Prop}; but it is false, so nothing has the type \code{2 + 2 = 5}. A proof \code{hp : P} can exist only when $P$ is true, so \code{hp : P} among a theorem's parameters is the assumption that $P$ holds.

An implication $P\Rightarrow Q$ can be used as a rule: give it a proof of $P$, and it returns a proof of $Q$. Lean writes it as \code{P -> Q}, with the same arrow as in $f:A\to B$, because a proof of \code{P -> Q} is a function that turns proofs of $P$ into proofs of $Q$. So if \code{h : P -> Q} and \code{hp : P}, then \code{h hp} is a proof of $Q$: the inference ``$P$ holds, and $P$ implies $Q$; therefore $Q$ holds.'' This way of reading statements and proofs is called \emph{propositions as types}, and it is all the theory this chapter needs.
