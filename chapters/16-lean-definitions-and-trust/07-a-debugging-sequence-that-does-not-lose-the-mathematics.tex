\section{A debugging sequence that does not lose the mathematics}\label{ch16:sec:debugging}
When Lean rejects a line, it is tempting to try one tactic after another, or to ask an assistant for anything that Lean will accept. Either habit can end with a file that Lean accepts and a statement that nobody wanted. Finding and removing the cause of an error is called \emph{debugging}. The following sequence keeps the mathematics in view while you debug.
\begin{enumerate}
\item \emph{Keep the statement fixed.} Do not edit the theorem's statement while you look for the problem.
\item \emph{Read the proof state.} Look at the goal, the available facts, and the error message.
\item \emph{Translate into ordinary mathematics.} Say in words what the goal claims and what each fact says.
\item \emph{Diagnose.} Decide which of four situations you are in.
\begin{itemize}
\item A \emph{difference of form}: the goal follows from the available facts, but something is written in a different form from the one the tactic expects.
\item A \emph{missing lemma}: the goal is true, but the proof needs a fact that is not yet available.
\item A \emph{mismatch of domains}: a variable ranges over a different set from the intended one.
\item A \emph{goal that does not follow}: in some situation where all the available facts hold, the goal fails. The goal may even be false outright, like the equation $2+1=4$.
\end{itemize}
\item \emph{Respond to the diagnosis.}
\begin{itemize}
\item For a difference of form, a one-line change, such as a \code{show} line, is usually enough.
\item For a missing lemma, find one, read its exact statement with the command \code{\#check} (described below), and make sure that its hypotheses hold in your situation before you use it.
\item For a mismatch of domains, go back to the statement contract and decide which domain was intended. If the statement has to change, change it on purpose and record the change, for instance in a comment above the theorem.
\item If the goal does not follow, stop looking for tactics: no tactic can derive it. First ask whether an earlier step caused the problem. In Section~\ref{ch15:sec:exists}, for example, offering the witness $2$ would have required a proof of the false equation $2+1=4$, and the remedy was a better witness. If the goal already fails to follow at the start of the proof, or after steps such as \code{intro} that only name arbitrary objects and assume the hypotheses, then the statement itself is false. Look for a \emph{counterexample}, an instance in which every hypothesis holds and the conclusion fails. It shows that the statement cannot be proved as it stands, and what to do next is a decision about the statement, as the second worked example below shows.
\end{itemize}
\end{enumerate}
Used in this way, Lean's messages become feedback on your mathematics, not obstacles to be cleared by whatever change Lean will accept.

\subsection*{Two worked examples}
\emph{A difference of form.} Leave out the line \code{show g (f a) = c} in the proof of \code{surj\_comp}, and keep the statement as it is (step~1). Reading the proof state (step~2), we see that Lean did not find the pattern \code{f a} at the \code{rw} line, and that the goal is \code{(fun x => g (f x)) a = c}. Translated (step~3), the goal says $(g\circ f)(a)=c$, and the facts $f(a)=b$ and $g(b)=c$ prove it. So the diagnosis (step~4) is a difference of form: the goal follows from the facts, but \code{f a} is not written in it, as Section~\ref{ch16:sec:surj} explained. The response (step~5) is the line \code{show g (f a) = c}. It changes the form of the goal but not its meaning, and the statement of the theorem is untouched.

\emph{A false statement.} Suppose we set out to prove \code{Surj (fun n : Nat => n + 1)}, the claim that the map $n\mapsto n+1$ on the natural numbers is surjective. After \code{intro y}, the goal is
\begin{center}
$\exists$\,\code{x, (fun n => n + 1) x = y}
\end{center}
For this arbitrary natural number $y$, we must find a natural number $x$ with $x+1=y$. Suppose that every tactic we try fails. Before trying more, translate the goal and test a small case. For $y=0$ we would need $x+1=0$, and no natural number $x$ satisfies this, because $x+1\ge1$. So the goal is false when $y=0$. The problem cannot come from an earlier step, because \code{intro y} only named an arbitrary target. Hence the statement itself is false, and the target $0$ is a counterexample. No tactic will ever close this goal. An assistant that was asked only to make Lean accept the file could succeed only by changing the statement, for example by adding a hypothesis as in Section~\ref{ch16:sec:irrelevant}, or by leaving a gap marked \code{sorry} (Section~\ref{ch16:sec:axioms}).

What should happen next depends on what was intended, and only a person can decide that. If the claim was meant to be about natural numbers, it is false, and Lean can prove that it is false:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
theorem not_surj_succ :
    Not (Surj (fun n : Nat => n + 1)) := by
  intro h
  cases h 0 with
  | intro n hn =>
    exact Nat.succ_ne_zero n hn
\end{lstlisting}
\end{minipage}\par
In Lean, \code{Not P} is defined to mean \code{P -> False}. So \code{intro h} assumes that the map is surjective and leaves the goal \code{False}. Applying \code{h} to the target \code{0} and unpacking the result gives a natural number \code{n} and a proof \code{hn} that $n+1=0$; the infoview shows \code{hn} in the unreduced form \code{(fun n => n + 1) n = 0}, which Lean treats as the same proposition. The last step uses a lemma from Lean's library, \code{Nat.succ\_ne\_zero}, and step~5 of the sequence tells us to read its exact statement before using it. To see the statement of any named theorem or lemma, put the command \code{\#check} followed by its name on a line of its own, outside every proof, just like the command \code{\#eval} of Section~\ref{ch15:sec:exists}. The output appears in the infoview when the cursor is on that line. Here the line \code{\#check Nat.succ\_ne\_zero} makes Lean print
\begin{center}
\code{Nat.succ\_ne\_zero (n : Nat) : n.succ} $\ne$ \code{0}
\end{center}
This reads like a declaration: the parameter \code{(n : Nat)} comes first, and the claim follows the colon. In the claim, \code{n.succ}, the \emph{successor} of \code{n}, is another way of writing \code{n + 1}, and $\ne$ is Lean's symbol for ``is not equal to'': \code{a} $\ne$ \code{b} means \code{Not (a = b)}. So the lemma says that $n+1\ne0$ for every natural number $n$, and it has no further hypotheses. Applied to our particular \code{n}, the lemma gives \code{Nat.succ\_ne\_zero n}, a proof of \code{Not (n + 1 = 0)}, that is, of \code{n + 1 = 0 -> False}. Applying this in turn to \code{hn} produces a proof of \code{False}, which is the goal.

If instead the claim was meant to be about integers, then the domain was mistranslated. Over $\ZZ$, the map $n\mapsto n+1$ is surjective: the target $y$ is reached by the input $y-1$. The repair is to change \code{Nat} to \code{Int}. This is a deliberate change of the statement, and the comment in the first line below records it as one:
\par\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}
-- Statement changed on purpose: Int in place of Nat.
theorem succ_surj_int : Surj (fun n : Int => n + 1) := by
  intro y
  refine Exists.intro (y - 1) ?_
  show y - 1 + 1 = y
  exact Int.sub_add_cancel y 1
\end{lstlisting}
\end{minipage}\par
The structure is that of \code{surj\_comp}: introduce a target, propose a witness, restate the goal in reduced form, and then prove the reduced goal. The library lemma \code{Int.sub\_add\_cancel a b} proves $(a-b)+b=a$ for all integers $a$ and $b$, and with $a=y$ and $b=1$ it is exactly the goal. The same step would fail for natural numbers. With truncated subtraction (Section~\ref{ch15:sec:exists}), the proposed witness for the target $0$ would be $0-1=0$, and $(0-1)+1=0+1=1$, not $0$.

If you run \code{\#print axioms} on these two theorems, Lean lists \code{propext}, which the library lemmas \code{Nat.succ\_ne\_zero} and \code{Int.sub\_add\_cancel} use. As Section~\ref{ch16:sec:axioms} explained, this is one of the standard axioms, and its appearance is no cause for concern.

Both responses keep the mathematics in view: the first turns a counterexample into a theorem, and the second corrects a translation openly. Neither hides a change of statement inside a proof that Lean merely accepts.
